# Site design rules

The public site is a rendering of `src/feed.json` and the canonical records in `src/data/`. The active interface is `public/preview/care-site/site.js` and `public/preview/care-site/style.css`, layered over `public/preview/site-md.css`. `SITE.md` defines page and navigation behavior.

Keep one civic type and icon system across Home, About, gap sections, and record pages. The approved interface uses a dark navy sidebar, white reading surface, teal interactions, restrained copper labels, and documentary imagery. Keep source context readable. A layout change must not change the meaning or provenance of a record.

The homepage is the street-dogs Overview. It opens with the question and attributed figures, then places a concise situation summary beside latest activity. Conditions, available care, improvements, and open questions follow; Crossover's current work and the record workspace come last. The work summary can be listened to. The site identity carries the guiding idea; About carries the wider technological and vocational context.

Images used for atmosphere are not evidence. Any documentary photograph used as evidence needs a source and context. Reported conditions, plans, firsthand observations, and measured outcomes must remain distinguishable in text and links.

The Overview listen control reads the same work-summary paragraphs shown on the page. The feed is one curated reading available in HTML and text. Neither should recite interface labels or include deployment dates as investigation updates. Lists and filters must use canonical published records; prototype examples cannot become facts by appearing in the design.
